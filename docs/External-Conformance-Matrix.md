# External Conformance Matrix

This matrix records what Agent-DID can prove against **external** specifications, using the specifications' own test vectors or independent implementations. It is deliberately separate from the [RFC-001 compliance checklist](RFC-001-Compliance-Checklist.md): that checklist measures Agent-DID against its own specification, while this matrix measures it against the standards it builds on.

## Rules

- A row is `PASS` only if a CI job named in the row runs the evidence on every relevant change (or on a nightly schedule) and fails when the evidence fails.
- Evidence is either an official vector set from the specification or its authors, or an independent implementation that is not derived from our code.
- Self-written tests, golden files generated by our own SDKs and library calls we merely wrap are **not** external evidence. They appear in the notes, never in the status.
- `PARTIAL` means some external evidence exists and the missing part is stated. `NOT COVERED` means there is none yet. Neither status may be rounded up in other documents.
- Other live documents (README, package READMEs, release criteria) must not claim conformance with a specification unless its row below is `PASS`.

## Maintaining this matrix

- Change a status only in the same PR that adds or removes its evidence, and keep the CI job column pointing at a job that exists in `.github/workflows/`.
- Pinned vector sets (`fixtures/didwebvh-test-suite.json`, `fixtures/jcs-vectors.json`) are updated deliberately, with a reason, never to make a failing job pass.
- A new standard that Agent-DID claims to implement needs a row here before any live document mentions conformance with it.
